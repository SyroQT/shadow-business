# Runs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a yearly minimum wage, a `full` / `snapshot` / `demo` CLI with a free-tier budget guard, a committed snapshot and example output, and a Docker image.

**Architecture:**
- `src/cli.py` dispatches to three modules:
  - `src/budget.py`: monthly usage from `raw.run_log` and the run caps;
  - `src/snapshot.py`: raw tables of one run to parquet plus a manifest;
  - `src/demo.py`: parquet into a fresh DuckDB, then `dbt build` and `export_leads`.
- `full` sets the caps through env vars and calls `src/pipeline.py`'s `main`.
- The minimum wage moves from a dbt var to the seed `minimum_wage`, joined on `year(sodra_month)`.

**Tech Stack:** Python 3.13, uv, DuckDB 1.5, dbt-duckdb 1.11, pytest, Docker (`python:3.13-slim`).

**Spec:** `docs/specs/runs-spec.md`. Yearly minimum wage: user ruling 2026-10-20 ("minimum wage is yearly"), amending `docs/specs/leads-spec.md` §3/§5/§6.

## Global Constraints

- **Demo:** no network, no keys, no `.env`, never opens `data/leads.duckdb`.
- **`full`:**
  - caps are `min(MAX_*, free_tier - used_this_month)`;
  - if remaining `<= 0` for either API it exits 2 before any client is built;
  - free tiers are `PLACES_FREE_TIER=1000` and `FIRECRAWL_FREE_TIER=1000`.
- **Secrets and API calls:**
  - no API keys in the image, snapshot, logs or examples;
  - never read or print `.env`;
  - no live API calls while implementing.
- **Committed demo snapshot:** run `2026-10_20261019T173429`, at `snapshots/2026-10_20261019T173429/`.
- **Example output:** `examples/2026-10/leads.csv` and `leads.md`, byte-identical to a fresh `demo`.
- **Minimum wage seed:** `minimum_wage.csv`, with year → EUR values 2024 → 924, 2025 → 1038, 2026 → 1153.
- **Commits:** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **January run:** the run month is in 2026 but the Sodra month is December 2025, so the wage is judged against €1038, not €1153. Test `test_min_wage_follows_sodra_year` (Task 1).
2. **Sodra year missing from the seed** (e.g. 2027 data): the build fails on a test; it must not silently treat the company as "not low wage". Test `test_min_wage_missing_year_fails_build` (Task 1).
3. **First-ever `full` with no DB file:** usage is 0 and the check creates no DB file. Test `test_used_this_month_missing_db` (Task 2).
4. **`snapshot` on a DB that dbt has not built** (`int_page_code_hits` missing): prints one stderr line, exit 1. Test `test_snapshot_requires_dbt_build` (Task 3).
5. **`demo` run twice:** the second run replaces `demo.duckdb`, so reviews are not doubled, and gives identical files. Test `test_demo_twice_identical` (Task 4).

## Rulings

- **Snapshot key check:** the spec's "grep for configured key values" is replaced by key-shaped patterns (`AIza[0-9A-Za-z_-]{20,}`, `fc-[0-9a-f]{20,}`, `Bearer `), scanned over the parquet contents read through DuckDB plus `manifest.json`. Reason: tests must not load `.env` keys. Cost if wrong: a key with an unusual shape is missed.
- **Unknown CLI command:** keeps argparse's standard usage error (exit 2). The one-line rule applies to a missing snapshot or a missing DB.
- **`demo --top` default:** `Settings(_env_file=None).leads_top_n`, which reads env `LEADS_TOP_N` only, never `.env`.

### Task 2: Budget and `full` (RUN-02)

**Files:**
- Create: `src/budget.py`, `src/cli.py`
- Modify: `src/settings.py` (add `places_free_tier: int = 1000`, `firecrawl_free_tier: int = 1000`)
- Test: `tests/test_budget.py`, `tests/test_cli.py`

**Interfaces:**
- `used_this_month(db_path: Path, now: datetime) -> dict[str, int]`
  - Keys are `"places"` and `"crawl"`; the value is the sum of `api_requests` from `raw.run_log` for that step, for rows with `started_at` in `[month start, next month start)` UTC.
  - It opens the DB read-only. A missing file or missing table gives zeros.
- `@dataclass(frozen=True) class Caps`, with fields:
  - `places_used`, `places_remaining`, `places_cap`;
  - `firecrawl_used`, `firecrawl_remaining`, `firecrawl_cap`.
- `plan_caps(settings: Settings, used: dict[str, int]) -> Caps`
  - remaining is `free - used`, floored at 0;
  - cap is `min(MAX_*, remaining)`.
- `format_caps(c: Caps) -> list[str]` returns exactly:
  - `places: used {u} of {free} this month, remaining {r}, run cap {cap}`
  - `firecrawl: used {u} of {free} this month, remaining {r}, run cap {cap}`
- `src/cli.py`: `main(argv: list[str] | None = None) -> int`, with subcommands `full [--dry-run]`, `snapshot`, `demo`.
  - **Exhausted budget:** `full` prints `full: {api} free tier used up this month ({used} of {free})` to stderr for each exhausted API and returns 2.
  - **Otherwise:** it sets `os.environ["MAX_PLACES_REQUESTS"]` and `["MAX_FIRECRAWL_PAGES"]` to the caps, calls `src.pipeline.main()`, and on 0 runs the snapshot command with defaults (Task 3).

  - `test_used_this_month_missing_db`: returns zeros, and the file is still absent afterwards.
  - `test_plan_caps_min_of_max_and_remaining`: used 950 places with MAX 1000 gives cap 50; Firecrawl used 0 with MAX 600 gives cap 600.

### Task 3: Snapshot (RUN-03)

**Files:**
- Create: `src/snapshot.py`
- Modify: `src/cli.py`
- Test: `tests/test_snapshot.py`

**Interfaces:**
- `latest_complete_run(con) -> str | None`: the max `run_id` having both `places` and `crawl` rows in `raw.run_log`.
- `write_snapshot(db_path: Path, run_id: str | None, out_dir: Path | None, force: bool = False) -> Path`. It writes:
  - **Parquet files**, via `COPY (...) TO ... (FORMAT parquet)`: `places`, `places_errors` and `web_pages` with `run_id = ?`.
  - **`sodra`:** rows whose `run_id` is one of the month's Sodra runs and whose `jarCode` is in `select distinct jar_code from intermediate.int_page_code_hits where run_month = ?`.
  - **`run_log`:** the rows with `run_id = ?`, or `step = 'sodra'` and `run_month = ?`.
  - **`manifest.json`:**
    - `run_id`, `run_month`, `created_at` (ISO UTC);
    - `git_commit` (`git rev-parse HEAD`, or null);
    - `rows` (a dict of file → count);
    - `sodra_source_url`;
    - `note: "Google Places content is a small demo sample"`.
  - **Defaults:** `out_dir` defaults to `snapshots/<run_id>`.
- `class SnapshotError(Exception)`. It is raised for:
  - a missing DB;
  - no complete run;
  - `int_page_code_hits` missing (message `snapshot: run dbt build first`);
  - a non-empty `out_dir` without `force`.
- **CLI:** `snapshot [--run-id] [--out] [--force]` prints the path. On `SnapshotError` it prints one stderr line and returns 1.

- [ ] Tests, on a fixture built with `load_lead_demo` and `build`, with `places` and `crawl` steps added:
  - `test_snapshot_files_and_manifest`: 6 files; manifest rows equal the source counts.
  - `test_snapshot_sodra_filtered`: add a Sodra row for an unrelated code; it is absent from the snapshot.
  - `test_snapshot_refuses_non_empty`: refused without `force`, overwritten with it.
  - `test_snapshot_requires_dbt_build`: one stderr line, exit 1.
  - `test_snapshot_no_key_patterns`: the patterns from Rulings, scanned over all parquet contents and the manifest.
- [ ] Implement, run the tests, commit `RUN-03: snapshot command`.

### Task 4: Demo (RUN-04)

**Files:**
- Create: `src/demo.py`
- Modify: `src/cli.py`
- Test: `tests/test_demo.py`

**Interfaces:**
- `newest_snapshot(root: Path = Path("snapshots")) -> Path`: the max directory name that has a `manifest.json`. Raises `DemoError` when there is none.
- `run_demo(snapshot_dir: Path, db_path: Path, out_dir: Path, top_n: int) -> Path | None`. It:
  1. deletes `db_path` (and its `.wal`);
  2. calls `connect(db_path)`, which creates the raw schema;
  3. runs `insert into raw.<t> by name select * from read_parquet(?)` for each file;
  4. runs `run_dbt(["build"], db_path)`, raising `DemoError` with the stdout tail on failure;
  5. returns `export_leads(db_path, out_dir, top_n)`.
- **CLI:** `demo [--snapshot] [--out output] [--top] [--db data/demo.duckdb]`.
  - `--top` defaults per Rulings.
  - On `DemoError` it prints one stderr line and returns 1.
